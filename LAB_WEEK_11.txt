1. When a user takes a picture, that picture is stored in a path based on the given 
URI. In which part of the code handles this? (Copy that part of the code as the 
answer) 

The part of the code that handles the creation of a temporary file and generates its URI 
before the picture is even taken is generatePhotoUri. This function prepares the destination 
for the camera app to save the image.The actual process of storing the final image from this 
temporary location into the shared MediaStore is handled by the insertToStore function. It 
copies the file from its initial URI to a new location in the MediaStore. Here is the 
insertToStore function which performs this action:


private fun insertToStore(fileInfo: FileInfo, contentUri: Uri,
                          contentValues: ContentValues
) {
    executor.execute {
        val insertedUri = contentResolver.insert(contentUri,
            contentValues)
        insertedUri?.let {
            val inputStream =
                contentResolver.openInputStream(fileInfo.uri)
            val outputStream =
                contentResolver.openOutputStream(insertedUri)
            IOUtils.copy(inputStream, outputStream)
        }
    }
}

2. In your FileInfo.kt, there are 5 attributes. On the first attribute, what does the URI 
refer to? And on the fourth attribute, what does relativePath refer to? 

Although FileInfo.kt is not provided, we can infer the meaning of its attributes from how 
they are created in generatePhotoUri and generateVideoUri.

* uri (First Attribute): This URI refers to the location of the temporary file created within the app's private external storage (getExternalFilesDir). It is generated by FileProvider to give secure access to this temporary file for other apps, such as the camera app. It is not the final MediaStore URI.
* relativePath (Fourth Attribute): This refers to the sub-folder name within the app's private storage where the temporary file is located (e.g., Pictures or Videos). It is later used to tell MediaStore where to save the final file in shared storage, ensuring a clean folder structure.

3.[Bonus] Explain the chronological order from when a user takes a picture until 
the file is stored in the MediaStore.

Here is the step-by-step process based on the provided code:
1. Generate a Temporary File URI: When the user decides to take a picture, the generatePhotoUri() function is called. It creates a File object representing a temporary image file (e.g., img\_1637123456.jpg) inside the app's private external directory (e.g., /Android/data/com.example.lab\_week\_11\_b/files/Pictures/). It then uses FileProvider to generate a secure content URI for this temporary file.
2. Launch Camera: This content URI is passed to the camera app when it is launched. This tells the camera exactly where to save the captured image.
3. User Takes Picture: The user captures the image using the camera app. The camera app saves the image data to the URI provided in the previous step.
4. Receive Image and Insert: After the picture is successfully taken, the insertImageToStore(fileInfo) function is called. This function takes the FileInfo object, which contains the URI of the temporary image file.
5. Copy to MediaStore: The insertImageToStore function calls the private insertToStore function. This function does the following:

* It first creates a new entry in the MediaStore for the image, which returns a new, final URI for the picture in public storage (like the Pictures directory).
* It then opens an InputStream to read the image data from the temporary file's URI.
* It opens an OutputStream to write data to the new MediaStore URI.◦Finally, IOUtils.copy() is used to copy the entire byte stream from the temporary file into the final location in the MediaStore, effectively "saving" it. This process runs on a background thread thanks to executor.execute.
